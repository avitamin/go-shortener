# Сервис сокращения URL на Go

## Обзор проекта

Это сервис сокращения URL на основе Go, который позволяет пользователям создавать сокращенные URL и перенаправлять на исходные URL. Сервис поддерживает несколько бэкендов хранения (база данных PostgreSQL, файловое хранилище или хранилище в памяти) и предоставляет как HTTP, так и API-эндпоинты для сокращения и разрешения URL.

### Ключевые особенности
- Сокращение URL с генерацией уникальных идентификаторов
- Поддержка нескольких бэкендов хранения (PostgreSQL, файловое, в памяти)
- Пакетная операция сокращения URL
- Управление URL на уровне пользователя
- Мягкое удаление URL пользователей
- Промежуточное программное обеспечение аутентификации
- Сжатие запросов/ответов
- Возможности аудита
- Миграции базы данных

### Архитектура
Приложение следует многоуровневой архитектуре с четким разделением обязанностей:
- **Слой обработки**: маршрутизация HTTP и обработка запросов с использованием маршрутизатора Chi
- **Слой сервиса**: бизнес-логика и оркестрация
- **Слой репозитория**: абстракция доступа к данным с поддержкой нескольких бэкендов
- **Слой модели**: структуры данных и доменные сущности
- **Слой промежуточного ПО**: сквозные задачи (логирование, аутентификация, сжатие)

## Сборка и запуск

### Предварительные требования
- Go 1.24+
- Docker и Docker Compose (для контейнерного развертывания)
- PostgreSQL (при использовании хранения в базе данных)

### Команды сборки
```bash
# Собрать бинарный файл локально
make build

# Или собрать напрямую с помощью Go
go build -o main ./cmd/shortener/main.go
```

### Запуск приложения

#### Использование Makefile
```bash
# Запустить с Docker Compose (включая PostgreSQL)
make up

# Остановить контейнеры
make down

# Просмотреть логи
make logs

# Очистить все
make clean
```

#### Прямой запуск Go
```bash
# Запустить с настройками по умолчанию
go run ./cmd/shortener/main.go

# Запустить с пользовательскими флагами
go run ./cmd/shortener/main.go -a=localhost:8099 -b=http://localhost:8099/ -d=postgres://postgres:postgres@localhost:54323/shortener?sslmode=disable
```

#### Параметры конфигурации
Приложение поддерживает конфигурацию через флаги командной строки и переменные окружения:

| Флаг | Переменная окружения | Описание | По умолчанию |
|------|---------------------|-------------|---------|
| `-a` | `SERVER_ADDRESS` | Адрес сервера | `localhost:8080` |
| `-b` | `BASE_URL` | Базовый URL для коротких URL | `http://localhost:8080` |
| `-f` | `FILE_STORAGE_PATH` | Путь к файловому хранилищу | `./runtime/storage` |
| `-d` | `DATABASE_DSN` | DSN базы данных | (нет) |
| | `SECRET_KEY` | Секретный ключ для аутентификации | `secret_key` |
| | `AUDIT_FILE` | Путь к файлу логов аудита | (нет) |
| | `AUDIT_URL` | URL удаленного сервера аудита | (нет) |

### Развертывание с Docker
Приложение может быть развернуто с использованием Docker Compose, которое настраивает как приложение, так и базу данных PostgreSQL:

```yaml
# выдержка из docker-compose.yaml
services:
  app:
    build: .
    ports:
      - "8099:8080"
    depends_on:
      - db
    environment:
      - SERVER_ADDRESS=:8080
      - DATABASE_DSN=postgres://postgres:postgres@db:5432/shortener?sslmode=disable
      - SECRET_KEY=secret_key
    command: ["./main"]
    restart: unless-stopped

  db:
    image: postgres:16-alpine
    container_name: postgres_db
    restart: unless-stopped
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: postgres
      POSTGRES_DB: shortener
    ports:
      - "54323:5432"
    volumes:
      - pgdata:/var/lib/postgresql/data
```

## API эндпоинты

### Основные эндпоинты
- `POST /` - Сократить URL (text/plain)
- `GET /{id}` - Перенаправление на исходный URL
- `POST /api/shorten` - Сократить URL (JSON API)
- `POST /api/shorten/batch` - Пакетное сокращение URL
- `GET /api/user/urls` - Получить URL пользователя
- `DELETE /api/user/urls` - Удалить URL пользователя
- `GET /ping` - Проверка работоспособности

### Бэкенды хранения
Приложение поддерживает три варианта хранения:
1. **База данных PostgreSQL** - постоянное хранилище с миграциями
2. **Файловое хранилище** - постоянное файловое хранилище
3. **В памяти** - энергозависимое хранилище для тестирования

### Схема базы данных
База данных PostgreSQL содержит таблицу `urls` со следующей структурой:
```sql
CREATE TABLE urls (
    id SERIAL PRIMARY KEY,
    original VARCHAR(255) NOT NULL,
    short VARCHAR(255) NOT NULL,
    user_id VARCHAR(255),
    is_deleted BOOLEAN DEFAULT FALSE
);
```

## Соглашения разработки

### Зависимости
Проект использует Go модули со следующими ключевыми зависимостями:
- `github.com/go-chi/chi/v5` - HTTP маршрутизатор
- `github.com/caarlos0/env/v6` - парсинг переменных окружения
- `github.com/golang-migrate/migrate/v4` - миграции базы данных
- `github.com/jackc/pgx/v5` - драйвер PostgreSQL
- `github.com/goccy/go-json` - обработка JSON

### Тестирование
Модульные тесты реализованы с использованием стандартного пакета тестирования Go. Моки генерируются с использованием `github.com/golang/mock`.

### Структура кода
- `cmd/` - точки входа в приложение
- `internal/` - внутренние пакеты (config, handler, service, repository и т.д.)
- `pkg/` - публичные пакеты (если есть)
- `migrations/` - файлы миграции базы данных
- `runtime/` - данные выполнения (расположение файла хранения по умолчанию)

### Промежуточное ПО
Приложение реализует несколько уровней промежуточного ПО:
- Логирование (с использованием zap logger)
- Сжатие/декомпрессия запросов
- Аутентификация
- Аудит
- Восстановление после паники

## Тестирование
Запуск тестов:
```bash
go test ./...
```
